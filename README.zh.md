# dsh-multi-dir-workspace

一个让 DSH 工作区可以同时使用**多个目录**的插件。

## 为什么需要它

DSH 核心的工作区严格绑定单个目录（`Workspace.path`）。插件无法修改核心（核心在
`app.asar` 里），所以本插件在公开扩展点之上叠加多目录能力：

1. **附加目录清单**，持久化在 `$DSH_HOME/multi-dir-workspace.json`。
2. **提示上下文**：把每个附加目录告诉模型（因此模型可以用绝对路径读取它们）。
3. **沙箱写入授权**：通过 `sandboxPolicy.registerWritableRoot` 为每个活动会话注册（读取本来就不受限）。
4. `workspace_directories` **工具**（`list` / `add` / `remove` / `cd`）以及供 UI 使用的 HTTP 路由。
5. 一枚位于全局标题栏、紧挨会话标题之前的**工作区 chip**（`conversation.header.leading`）。
   chip 显示当前目录名，点开后弹出以 chip 为锚点、带指向箭头的面板（默认向上展开，
   上方空间不足时翻到下方），用来添加 / 切换 / 移除目录，目录选择使用系统原生选择器。

## 用法

- chip 就在标题栏里紧挨会话标题，显示当前目录名，所以每个会话都能看到，空白的「新会话」页面也在。
- 点开面板：
  - **+ 添加目录** 打开系统原生目录选择器，把选中的目录附加进来。
  - **切换** 把该会话的工作目录切到那个目录。
  - **移除** 把它从工作区摘掉。
- 也可以直接让模型做：*「把 D:\shared\libs 加到工作区」* —— 它会调用 `workspace_directories` 工具。
- 内置的 `working_directory` 工具同样可以用来 `cd`。

## 说明与限制

- chip 只注册在一个地方（root scope 的槽位），所以整页只渲染一次，也不依赖会话是否存在。
- v1 中附加目录是全局的（一份清单），不是每个工作区各自一份。
- 写入授权只在运行时有效，会话启动时重新注册；在 Windows 上只有 DSH 自己的文件工具会遵守额外授权
  （子进程权限不变）。
- 路径用 `path.resolve` 规范化；符号链接根目录会被沙箱策略拒绝写入，但仍然可读。
